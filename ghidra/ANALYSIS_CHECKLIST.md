# Ghidra 分析检查清单

以下为推荐的静态分析步骤（仅供参考）。在进行任何动态分析前，请确认处于隔离环境。

1. 初始准备
   - 确认样本哈希（SHA256）并记录。不要把样本上传到公开仓库。
   - 在离线/隔离的 VM 中创建 Ghidra 项目并将样本导入到本地项目中。

2. 基本信息收集（无需运行）
   - 查看文件头（PE header）、入口点、节（sections）信息。
   - 导出 import / export 表，识别依赖的系统 API（例如 CreateProcess、WriteFile、Registry 等）。
   - 计算熵（entropy），识别是否包含嵌入资源或压缩/加密段。
   - 导出字符串（ASCII/Unicode），寻找可疑命令、URL、注册表键等。

3. 代码分析（静态）
   - 让 Ghidra 做初始分析，检查函数边界与交叉引用（xref）。
   - 标注可疑函数（自启动、持久化、加密/解密例程、网络通信等）。
   - 生成函数调用图或导出函数列表用于后续报告。

4. 高级静态分析
   - 查找硬编码配置、嵌入载荷、Base64 或其他可疑编码字符串（仅提取文本）。
   - 识别加/解密算法与关键数据结构。
   - 注释关键位置并将注释导出为报告的一部分。

5. 动态分析（仅在严格隔离环境下，需额外授权）
   - 如果必须运行样本，请在完全离线的 VM /沙箱 中运行并使用监控工具（procmon、网络监控等）。
   - 记录行为并与静态分析结论对比。不要将样本或运行镜像上传到公开存储。

6. 输出与分享
   - 导出非敏感产物：函数列表、字符串提取、静态分析笔记、截图、哈希值。将这些文件提交到仓库或发布报告。 
   - 对于可能涉及敏感信息的发现（例如泄露的凭证），先与仓库维护者沟通再决定披露范围。

附注
- 本清单为通用建议；实际分析流程请根据样本属性与团队流程调整。
